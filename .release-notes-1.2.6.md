## v1.2.6 - agent guidance for the empty-run problem

Agents were guessing inputs (no state, no coordinates, misspelled fields) and paying actor-start fees for runs that answered nothing. This release makes the right input the easy one.

- **Agent guide in the handshake.** `initialize` now returns `instructions`: search -> describe -> run, scope every call, real codes and ISO dates, start small, how to read failures, zero rows and `null`.
- **Verified example inputs.** `describe-gov-data-tool` returns `must_supply`, `example_input` (the actor's prefill, run by Apify QA) and up to two run-verified `examples` from published demo tasks (190 across 123 tools).
- **Free local pre-flight.** A missing required field, an unknown input name or an invalid enum value returns `NOT_RUN_INPUT_INVALID` with the example to copy. No run is started and nothing is charged. All 313 verified inputs pass it (no false rejections, asserted in tests).
- **Next step on unhelpful results.** Failed runs carry `next_step`, `must_supply` and `example_input`; zero-row successes say to check scope before concluding nothing exists. In-flight runs (timeout / unsettled) are not told to change their input.
- Catalog regenerated against live (123 tools), including `medicaid-exclusion-screener`'s new `fullList` input.

Tests 85 -> 97, mutations 40 -> 47, all caught.
